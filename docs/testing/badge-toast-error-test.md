## 뱃지(배지) 에러 토스트 테스트 가이드

목표는 **뱃지 Firestore 관찰 중 발생하는 네트워크/Firebase 에러가 `AuthErrorMapper`를 통해 토스트로 표시되는지** 검증하는 것입니다.

### 1) 사전 조건

- **테스트 화면**: `BadgeScreen` (앱 상단의 뱃지 아이콘 → 뱃지 화면 진입)
- **토스트 이벤트 흐름**
  - `BadgeRepositoryImpl`에서 뱃지 컬렉션에 대해 **`get(Source.SERVER)`로 서버 1회 조회** 후 스냅샷 리스너를 붙임(오프라인에서 리스너만 쓰면 캐시로 조용히 동작해 에러 콜백이 안 오는 경우가 많아서).
  - 서버 조회 실패 또는 리스너에서 전달된 에러 → Flow가 실패로 끝남
  - `BadgeViewModel`에서 `collect`를 `try/catch`로 감싸 예외 수신 → `UiEvent.ShowToast(AuthErrorMapper.map(e))` emit (`MutableSharedFlow`는 `extraBufferCapacity`로 이벤트 유실 완화)
  - `BadgeScreen`에서 `UiEvent.ShowToast` 수신 → `Toast.makeText(...).show()`

### 2) 기대 결과(성공 기준)

- 뱃지 화면 진입 후(또는 뱃지 화면이 열린 상태에서) 아래 시나리오를 수행했을 때 **토스트가 표시**되어야 합니다.
- 토스트 문구는 `presentation/.../AuthErrorMapper.kt`의 매핑 결과를 따릅니다.
  - 네트워크 계열: `"네트워크 연결 상태가 좋지 않습니다"`
  - Firestore 예외(권한 등): `"DB 저장 실패"` (예외 클래스명이 Firestore 예외로 판별될 때)
  - 타임아웃: `"서버 지연"`
  - 그 외: `"기타"`

### 3) 테스트 시나리오 A — 네트워크 끊기(가장 쉬움)

**의도**: 서버 조회(`Source.SERVER`)가 실패하도록 해 `"네트워크 연결 상태가 좋지 않습니다"`(또는 `AuthErrorMapper`가 매핑한 메시지) 토스트를 확인합니다.

> 중요: **이미 뱃지 화면에서 서버 조회에 성공한 뒤** 네트워크만 끊으면, 스냅샷 리스너가 캐시만으로 계속 동작해 **토스트가 안 뜰 수 있습니다.** 재현할 때는 아래처럼 **「끊은 다음에 화면 진입」**을 권장합니다.

- **Android Emulator**
  - 에뮬레이터의 Extended controls(… 버튼) → **Cellular** 또는 **Wi‑Fi** 비활성화, 또는
  - macOS에서 네트워크(와이파이)를 끊거나, 또는
  - 에뮬레이터에서 비행기 모드(가능한 경우) ON
- **실기기**
  - 비행기 모드 ON 또는 Wi‑Fi/데이터 OFF

**절차(권장)**

1. 앱을 완전히 종료하거나, 뱃지 화면이 아닌 곳(예: 메인)에 둔다.
2. **네트워크를 끈다**(비행기 모드 등).
3. 앱 실행 → 로그인된 상태 유지
4. 상단 뱃지 아이콘으로 **뱃지 화면에 처음 진입**(또는 뒤로 나갔다가 **네트워크가 꺼진 채로** 다시 진입)

**기대 결과**

- 토스트: **"네트워크 연결 상태가 좋지 않습니다"**(또는 Firestore가 래핑한 예외에 따라 `"DB 저장 실패"` 등 `AuthErrorMapper` 규칙에 맞는 문구)

**팁**

- 재현이 안 되면 **앱 강제 종료 → 네트워크 OFF → 앱 재실행 → 뱃지 화면 진입** 순서로 다시 시도합니다.

### 4) 테스트 시나리오 B — Firestore 권한 거부(Permission Denied)

**의도**: Firestore에서 권한 문제를 일으켜 FirebaseFirestoreException을 발생시키고 `"DB 저장 실패"` 토스트가 뜨는지 확인합니다.

#### 방법 1) 테스트용 계정으로 권한이 없는 경로 접근

프로젝트의 Firestore 보안 규칙에 따라, 특정 사용자/상태에서 `users/{uid}/badges` 읽기가 거부될 수 있습니다.

**절차**

1. 권한이 제한된 테스트 계정으로 로그인
2. 뱃지 화면 진입

**기대 결과**

- 토스트: **"DB 저장 실패"**

#### 방법 2) Firestore Rules를 잠깐 강하게 막고 확인(팀/개인 개발 환경에서만)

Firebase Console에서 Firestore Rules를 임시로 다음처럼 바꾸면(모든 read 거부) 재현이 쉽습니다.

> 주의: 이 변경은 모든 사용자/환경에 영향을 줍니다. 로컬/개발 프로젝트에서만 수행하세요.

예시(개발용):

```txt
match /{document=**} {
  allow read, write: if false;
}
```

**절차**

1. Rules 반영 후 앱에서 뱃지 화면 진입

**기대 결과**

- 토스트: **"DB 저장 실패"**

### 5) 테스트 시나리오 C — 타임아웃/지연 상황

**의도**: 네트워크 품질을 나쁘게 만들어 타임아웃/지연 관련 오류를 유도하고 `"서버 지연"` 토스트를 확인합니다.

- 에뮬레이터/기기 네트워크를 **매우 느리게** 만들거나, 순간적으로 끊었다가 연결하는 방식으로 유도합니다.
  - (가능하면) 에뮬레이터 네트워크 속도 제한 기능 사용

**기대 결과**

- 토스트: **"서버 지연"**

> 참고: 이 시나리오는 환경에 따라 재현성이 떨어질 수 있어, A(네트워크 끊기)나 B(권한 거부)가 더 안정적입니다.

### 6) 디버깅 체크리스트(토스트가 안 뜰 때)

- 뱃지 화면(`BadgeScreen`)에서 이벤트 수신이 실제로 동작하는지 확인
  - 뱃지 화면을 열어둔 상태에서 에러를 발생시켰는지(백그라운드/다른 화면이면 토스트가 안 보일 수 있음)
- **서버 조회가 이미 성공한 뒤** 오프라인만 만든 경우, 리스너가 캐시만 쓰면 **에러가 없을 수 있음** → 시나리오 A는 **오프라인 후 진입**으로 다시 시도
- 로그인 상태 확인
  - `BadgeViewModel`은 `accountUseCase.getAccountInfo().value`가 null이면 관찰을 시작하지 않습니다.
